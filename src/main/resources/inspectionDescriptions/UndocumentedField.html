Reports a field the endpoint validates and the docblock does not mention.

A different failure from a dangling reference: both sides are impeccable on their own. The rules are correct, the docblock parses, the generated specification validates — and it describes a different set of fields from the one the endpoint accepts. Nothing but a comparison can see it.

Measured on two real applications: of 52 endpoints with both readable rules and a docblock, nine disagreed. Among them a public integration API whose email delivery could not be called from its own documentation.

Only literal rule arrays are read. array_merge, Rule::when, rules built from config: the whole array is discarded rather than half-read, because a field missing from a partial reading looks exactly like a field nobody documented.

The reverse — documented and not validated — is deliberately not reported: password_confirmation comes from the confirmed rule, and some fields are validated dynamically. Both are correct documentation.
